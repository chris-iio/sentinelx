   - Module docstring explaining purpose, security notes about raw_line content
   - `from __future__ import annotations`
   - Imports: `import ipaddress`, `import io`, `import logging`, `import re`, `from datetime import datetime, timedelta`, `from typing import IO`, `from app.ssh.models import LoginEvent, ParseSummary`
   - `logger = logging.getLogger(__name__)`
   - Two compiled regex patterns for BSD syslog full-line match:
     ```python
     _BSD_ACCEPTED_RE = re.compile(
         r'^(?P<month>[A-Za-z]{3})\s+(?P<day>\d{1,2})\s+(?P<time>\d{2}:\d{2}:\d{2})\s+'
         r'\S+\s+sshd\[\d+\]:\s+Accepted\s+(?P<method>\S+)\s+for\s+(?P<user>\S+)\s+'
         r'from\s+(?P<source>\S+)\s+port\s+\d+'
     )
     ```
   - RFC3339 full-line match:
     ```python
     _RFC3339_ACCEPTED_RE = re.compile(
         r'^(?P<ts>\S+)\s+\S+\s+sshd\[\d+\]:\s+Accepted\s+(?P<method>\S+)\s+for\s+(?P<user>\S+)\s+'
         r'from\s+(?P<source>\S+)\s+port\s+\d+'
     )
     ```
   - A partial-match regex to detect sshd lines that start with "Accepted" but fail full extraction (for D-06 warning):
     ```python
     _PARTIAL_SSH_RE = re.compile(r'sshd\[\d+\]:\s+Accepted\s+')
     ```
   - Helper `_classify_source(source: str) -> tuple[str | None, str | None]`:
     - Try `ipaddress.ip_address(source)` — if succeeds, return `(source, None)`
     - On `ValueError` — return `(None, source)` (hostname case)
   - Helper `_parse_bsd_timestamp(month: str, day: str, time_str: str, now: datetime) -> datetime`:
     - Use `datetime.strptime(f"{now.year} {month} {day} {time_str}", "%Y %b %d %H:%M:%S")`
     - Year rollover: `if dt > now + timedelta(hours=24): dt = dt.replace(year=now.year - 1)`
     - Return `dt`
   - Main function `parse_auth_log(stream: IO[bytes] | IO[str], *, now: datetime | None = None) -> tuple[list[LoginEvent], ParseSummary]`:
     - If `now is None: now = datetime.now()`
     - Handle bytes vs text stream: if `isinstance(stream, (io.RawIOBase, io.BufferedIOBase))` or stream has `mode` attr with 'b', wrap in `io.TextIOWrapper(stream, encoding="utf-8", errors="replace")`
     - Simpler approach: read all content as string, split by newlines. If stream yields bytes, decode UTF-8 with errors="replace"
     - Initialize counters: `parsed_count = 0`, `skipped_count = 0`, `warning_count = 0`, `total_lines = 0`, `events: list[LoginEvent] = []`
     - For each line (1-indexed line_number):
       - `total_lines += 1`
       - Strip trailing whitespace
       - Try BSD regex match first. If match:
         - Extract month, day, time, method, user, source from named groups
         - Parse timestamp via `_parse_bsd_timestamp()`
         - Classify source via `_classify_source()`
         - Create LoginEvent, append to events
         - `parsed_count += 1`
         - `continue`
       - Try RFC3339 regex match. If match:
         - Extract ts, method, user, source from named groups
         - Parse timestamp via `datetime.fromisoformat(ts)`
         - Classify source
         - Create LoginEvent, append
         - `parsed_count += 1`
         - `continue`
       - If neither matched, check partial: `_PARTIAL_SSH_RE.search(line)`:
         - If partial match: `logger.warning("Line %d partially matched SSH pattern but failed extraction: %r", line_number, line)`
         - `warning_count += 1`
         - `continue`
       - Otherwise: `skipped_count += 1`
     - Return `(events, ParseSummary(total_lines, parsed_count, skipped_count, warning_count))`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| auth.log content -> parser regex | Attacker-controlled log content (usernames, hostnames) enters regex engine and LoginEvent fields |
| stream bytes -> UTF-8 decode | Malformed UTF-8 in log file could cause decode errors |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Denial of Service | Regex engine | mitigate | All regexes use anchored patterns (^) and non-greedy \S+ groups. No nested quantifiers that could cause catastrophic backtracking. Regex patterns are compiled once at module level. |
| T-06-07 | Tampering | LoginEvent.username/hostname | accept | Values stored as-is from log. Rendering is Phase 9's responsibility (textContent enforcement). Parser does not execute or evaluate any extracted content. |
| T-06-08 | Denial of Service | Large file processing | mitigate | Parser processes line-by-line (not loading entire file into memory at once for regex). MAX_CONTENT_LENGTH (5 MB, from Plan 02) bounds input size before parser is invoked. |
| T-06-09 | Tampering | UTF-8 decode | mitigate | Use `errors="replace"` when decoding bytes to prevent UnicodeDecodeError from malformed input. Replaced characters are harmless in regex matching (they won't match any pattern). |
</threat_model>
