08 · Risks and cleanup

Generated files

__pycache__ directories exist in app/tests/tools. Keep ignored and remove from release artifacts.

Config validation tightened

Effective app config is validated after overrides, including admission limits, trusted hosts, allowed API hosts, and SameSite value.

Supply-chain convenience targets hardened

Tailwind/esbuild installer targets now verify downloaded binaries against pinned SHA-256 checksums.

Broad exception handlers

Many are intentional bounded-failure paths. Continue annotating broad catches so reviewers can distinguish safety policy from accidental swallowing.

09 · Recommendations

  1. Keep the architecture. The current seams are clear and testable.
  2. Keep config validation tight. Continue validating effective app config after overrides.
  3. Clean generated artifacts before release. Exclude caches, local state, secret-bearing files, and dependency directories.
  4. Maintain checksum-pinned binary downloads. Update hashes only with intentional tool upgrades.
  5. Preserve verification lanes. Use make verify-fast for routine changes and make verify-deep for browser/enrichment flow changes.
